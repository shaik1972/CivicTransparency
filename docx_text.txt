Common Database Conventions Primary keys: UUID for major domain entities; composite keys where appropriate for junction tables. Public identifiers: Separate human-readable complaint_reference from internal complaint_id. Timestamps: TIMESTAMPTZ, stored in UTC. GIS: PostGIS geography/geometry for coordinates and spatial queries. Media: Object storage for bytes; PostgreSQL stores metadata/references. Concurrency: Optimistic locking/version on important mutable aggregates. Soft deletion: Not universal; use only where required by domain/retention. JSONB: Only for genuinely variable configuration/metadata. 5. Important Indexes complaint: unique(complaint_reference); (city_id, created_at); (category_id, created_at). workflow: (current_state); (current_state, started_at). complaint_location: GIST(point); GIST(public_geometry). evidence: (complaint_id); unique/usable index on sha256. assignment: (complaint_id, unassigned_at); (department_id, assigned_at). routing_rule: (is_active, priority) plus relevant geography/category fields. routing_decision: (complaint_id, decided_at). complaint_sla: (status, due_at). notification: (status, created_at); (recipient_user_id, created_at). audit_event: (entity_type, entity_id, occurred_at); (correlation_id). public_complaint: (public_status, city_name); (category_name, public_status); (published_at). 7. Key Integrity Rules Complaint identity is private; citizen information is never exposed through authority/public APIs. Each complaint has exactly one workflow record; workflow.current_state is the lifecycle source of truth. Routing decisions are historical and do not change when routing rules change. An SLA is instantiated from a policy so later policy changes do not silently alter running complaints. Exact coordinates remain private unless the exposure policy explicitly permits them; public_geometry is generalized. Only approved/sanitized media derivatives may be published. Audit events are append-only and should contain no unnecessary PII. Configuration changes must themselves be auditable. 8. Transaction &amp; Event Boundaries Complaint creation should atomically persist the complaint, initial workflow, location when provided, and routing/SLA information that must be consistent. Public projection, analytics, notification delivery, media processing and external moderation integrations are asynchronous and must not block the core transaction. 9.
